# Changelog

Per-package changelogs are generated by changesets from 0.1.0 onwards. This
file records the release-level notes.

## 0.1.0

First public release. Deliberately 0.x: the shape of the config layers and the
module-package contract are the two things most likely to need a breaking
change once other people's stores start pushing on them.

Everything numbered before this was private development and is not published.

### Design decisions worth knowing

- **A store's differences are configuration, not a fork.** Selectors, slugs,
  labels, inputs and capability flags merge core → theme → project, so a store
  adapts the suite by editing five JSON files.
- **A test that cannot run is an exclusion with a reason code**, never a silent
  skip. `not-applicable`, `platform-gap` or `client-bug`, printed at run start,
  so the platform's own debt cannot hide among a store's real limitations.
- **Assertions read state back.** A success flash message proves only that a
  controller did not throw.
- **Module tests are packages, not branches.** Anything that exists only when a
  particular Magento module is installed lives in its own `e2e-m2-module-*`
  package and is discovered automatically.
- **Five CI gates, because a gate that covers less than it claims is worse than
  none**: cross-theme parity, scaffolder version pins, unread selector keys,
  the coverage matrix against the specs on disk, and module packaging. The last
  one exists because the other four all passed while every module package was
  undiscoverable from a registry install.
