# @samjuk/e2e-m2-module-smile-elasticsuite

E2E tests for [Smile-SA/elasticsuite](https://github.com/Smile-SA/elasticsuite).

The one module in this repo that does not *add* a storefront section. It
**replaces** two the core suite already tests: catalog search and layered
navigation. So the tests here are deliberately the ones the stock engine would
fail.

## Store requirements

| Config path | Value |
|---|---|
| `catalog/search/engine` | `elasticsuite` |
| `smile_elasticsuite_core_base_settings/es_client/servers` | `host:port`, e.g. `opensearch:9200` |

Then reindex `catalogsearch_fulltext`.

Set the ElasticSuite client **before** `setup:upgrade`: its data install talks
to the cluster, and with the default `localhost:9200` the upgrade fails with
"No alive nodes found in your cluster".

## What it covers

| Test | Why the stock engine would fail it |
|---|---|
| The autocomplete offers products, not only search terms | Magento's own suggest endpoint returns terms and nothing else |
| A product suggestion resolves to the page it names | A stale index suggests products that no longer exist |
| The store search term returns products | Baseline |
| A misspelled query falls back to the closest matches | Magento returns nothing for a misspelling; ElasticSuite fuzzy-matches and says so in its own notice |
| An unmatchable query still returns nothing | The counterweight. Without it, "falls back to the closest matches" would also pass on an engine that returned everything |

The misspelling is generated by doubling the last letter of the store's own
`inputs.search.query`, so it is an edit distance of one from a word the
catalogue definitely contains, whatever that word is, on whatever store.

## What installing this found

Two platform bugs, both fixed in core rather than worked around here:

- The **search-engine health guard** looked up
  `catalog/search/<engine>_server_hostname`. ElasticSuite keeps its servers
  somewhere else entirely, so the guard refused to run against a perfectly
  healthy store, the one failure mode it must never produce.
- The **layered navigation page object** clicked a filter group's title
  unconditionally. The title is a toggle, so on a store whose filters are
  already open (ElasticSuite's are), it closed the group it meant to open.
